1. The big picture

A four-phase plan for moving one classroom of 20 machines to Debian, with pupils signing in with their Active Directory accounts, home folders on a central server and OneDrive through rclone, wrapped in a small Express and PostgreSQL app that keeps notes, uploaded files and tick-box progress against every step. The app was built in about twenty hours across 9 and 10 December 2024, with the tick boxes finished on 12 December; the repository does not record whether the pilot itself was carried out.

So there are two things to learn from here. One is the plan: how a Linux machine joins a Windows domain, boots its installer from the network, and is managed in bulk. The other is the tracker, whose short history is full of small, instructive mistakes: where data should live, what identifies a step, and what a web server should and should not hand out.

Everything below comes from the commits, the plan pages and the code. The progress data (notes and tick boxes) exists only as database dumps, which I did not open, so this page says nothing about how far the pilot got. Where I explain how Active Directory, PAM, PXE or rclone work, or point out gaps in the plan, that is background knowledge and my reading of the relevant documentation, not something the repository shows being tried.

The one-line summary A plan is only as good as its first test run, and a tracker is only as good as the identifiers it stores things under. Give every step one stable ID, keep secrets and data out of anything a web server serves, and test each part of a plan on one machine before trusting it on twenty.

2. The plan in four phases

The whole plan arrived in the first commit (e173a06, 2024-12-09 22:11): an overview page and a detailed page for each phase, 32 files and about 3,000 lines. Each step has "More Info" panels with example commands and configuration. Later commits added note boxes, upload boxes and tick-box IDs to these pages.

A separate learning-objectives page lists five project-level objectives and a set for each phase, each with a date, a link and a comments box. The repository does not say whose objectives they are.

Network isolation and network installs

The pilot machines were to sit on their own VLAN: a separate network carved out of the same switches, so their traffic, and above all the pilot's own DHCP server, stay apart from the school's network. A second DHCP server on the main network would hand out wrong addresses to other machines, which is why Phase 1's final checks begin with the isolation.

PXE boot works like this: the network card's firmware asks DHCP for an address, the reply also names a boot server and a file, the card fetches that small boot program over TFTP, and the boot program loads the Debian installer, which then installs over the network. dnsmasq can provide the DHCP and TFTP parts on its own, which is why the plan uses it for both.

Managing twenty machines at once

Ansible logs in to each machine over SSH and makes it match a description. The plan has the usual pieces: an inventory file listing the machines, SSH keys so no password is typed 20 times, an ad-hoc ansible all -m ping to prove it can reach them, a playbook that installs packages with the apt module, and a template (smb.conf.j2) whose task notifies a "restart samba" handler, so the service restarts only when the file actually changes.

3. Joining Linux machines to Active Directory

What has to happen

For a pupil to sign in to a Debian machine with the same username and password as on Windows, the machine needs four things, and in the plan Samba's Winbind provides all of them:

  1. Membership of the domain. net ads join creates a computer account in AD and stores a shared secret, so the machine can talk to the domain controllers over Kerberos. smb.conf needs security = ads, the domain's short name (workgroup) and its Kerberos realm.
  2. Users and groups (NSS). Linux finds users through the Name Service Switch. With libnss-winbind and winbind added to the passwd and group lines of /etc/nsswitch.conf, AD accounts appear to getent passwd, ls -l and everything else. The plan's checks are wbinfo -u (Winbind can list domain users) and getent passwd (the rest of the system can see them).
  3. Passwords (PAM). Logins are checked through PAM. libpam-winbind adds pam_winbind.so, which passes the password to AD.
  4. A home folder. The plan adds pam_mkhomedir.so to create one from /etc/skel on first login, and a [homes] share on the file server.

The plan also sets winbind use default domain = yes, so pupils type a bare username rather than DOMAIN\username, and template shell = /bin/bash, the shell AD users get.

What the plan does not yet cover

These are from my reading of the Samba, PAM and Debian documentation, not from anything recorded in this repository.

  • ID mapping. Linux identifies users by number (UID), AD by a long SID. Something has to turn one into the other, and the example smb.conf has no idmap config lines. Samba's guide to domain members treats them as required. A backend such as rid or ad is also what gives the same pupil the same UID on all twenty machines and on the file server, which shared home folders depend on.
  • Mounting the home folders. pam_mkhomedir creates an empty local folder; it mounts nothing. For "the same files on every machine" (the plan's own Phase 3 test creates a file on one machine and looks for it on another), the server's [homes] share has to be mounted at login, for example with pam_mount or an automounter. As written, that test would fail.
  • Editing PAM files by hand. On Debian, /etc/pam.d/common-* are maintained by pam-auth-update, which packages call when they are installed or upgraded. Lines added by hand inside its managed block can be rewritten; the supported route is to enable the profile (Winbind installs one).
Trap: an admin password on the command line The plan's join command passes the administrator's name and password with -U, and its own note says to "use a vault for security". A password typed as an argument ends up in shell history and is visible to other users in the process list while the command runs; in an Ansible ad-hoc command it is also in the log. Let the command prompt for it, or keep it in Ansible Vault.

4. OneDrive through rclone

rclone mount presents a cloud store as an ordinary folder through FUSE: files are fetched when opened instead of being synchronised in advance. To reach a OneDrive it needs an OAuth token, which a person obtains by signing in through a browser during rclone config, and which is stored in that person's rclone.conf.

That is the gap in the plan (again my reading, not something tried here): its example stores the configuration in one administrator's home folder, which gives access to one OneDrive. Every pupil would need their own token, created by signing in once on the machine, or something that hands one out at login. The example systemd unit has two further problems as written: systemd does not expand ~ in ExecStart (it offers %h for the home folder), and --daemon makes rclone's first process exit straight away, which systemd takes as the service ending. rclone's own documentation runs the mount with Type=notify and no --daemon.

5. The tracker app

How it grew

Saving as you type: debounce and upsert

The first database version (9150ddf) sent a request on every input event, and each request ran INSERT INTO notes (phase, step, content). Typing one sentence created dozens of rows. e6b7d15 fixed it twice over. A debounce restarts a one-second timer on every keystroke and only saves when the timer runs out, so a burst of typing becomes one request. An upsert, INSERT … ON CONFLICT (phase, step) DO UPDATE SET content = EXCLUDED.content, makes each save replace the step's note instead of adding another. The upsert needs a unique constraint on (phase, step), which is why the README's set-up step mentions one.

Verified: what the fix changed The diff of e6b7d15 adds a debounce(saveNote, 1000) wrapper in plan/add-step-notes.js and changes the server's statement to ON CONFLICT (phase, step) DO UPDATE. The debounce cuts the number of requests; the upsert is what stops duplicate rows.

What is a step called?

By the end, the same step was identified in three different ways, depending on what was being stored:

  • Notes use the phase number read from the page title with /Phase (\d)/, plus the text of the step's heading. Reword a heading and its note is orphaned.
  • Uploaded files use the phase and the step number from data-step-number and the button's uploadFile(1, 2). An upload also writes a placeholder note under that number, so the notes table holds keys of both kinds.
  • Tick boxes use string IDs such as sub-step-1-1-1, added to every checkbox in 7e79583 ("added uid to each checkbox").
Trap: the page's IDs and the database's IDs did not match After 7e79583 the page knew each tick box by a string like sub-step-1-1-1, but the Sequelize model's key was an auto-increment integer, and the update route looked boxes up with findByPk(id). ed03d07 ("tick boxes working") changed Checkbox.stepId from an INTEGER referencing steps.id to a STRING referencing steps.stepId, and made the routes look boxes up by that string. The HTML defines which steps exist, so the database has to use the HTML's names for them.

The fix bought simplicity at a price. The earlier update route also marked a step complete when all its boxes were ticked, and a phase complete when all its steps were; that roll-up was removed. And the new GET /api/checkboxes/:stepId creates the step and checkbox rows if they do not exist, attaching every new step to phase 1 (phaseId: 1, // Set the appropriate phaseId), so merely opening a page writes to the database.

Two ways into one database

The notes and files tables are reached with hand-written SQL through pg; the phases, steps, checkboxes and learning objectives through the Sequelize ORM, which runs sequelize.sync({ alter: true }) at every start-up and alters those tables to match the models. Only the Sequelize tables are defined anywhere in the code. The notes and files tables exist only in the database (and presumably the dumps), so the repository alone cannot rebuild them.

Trap: a dependency that was installed but never declared b9acda8 (2024-12-10 05:43) made server.js require Sequelize, but sequelize was only added to plan/package.json in ed03d07, two days later. For those two days it worked on the machine that already had it and would have failed after a fresh npm install. (The merit tracker had the same slip with node-cron.)

What the server hands out

9150ddf served static files from path.join(__dirname, 'plan'), but server.js already lives in plan/, so it pointed at a plan/plan folder that did not exist. e6b7d15 changed it to express.static(__dirname), "the project root". That works, but the folder it serves also holds server.js and the model files (all three contain the database password), the database dumps in plan/, and, when the server is started from plan/, the uploads/ folder. Anyone who can reach the port can download them. The comment on that line now says "Serve static files from the 'public' directory", which is not what it does.

Trap: serving the folder the code lives in express.static hands out every file in its folder except dotfiles. Point it at a folder that holds only what browsers should see (a public/ folder), and keep credentials in environment variables or an ignored .env, never in a served file. Here the fix for one bug (a wrong path) created a worse one, and the comment drifted away from the code.
Verified: one copy-paste slip in the upload boxes In plan/phase-1-detailed.html, the "Browse" label of step 2 has for="file-upload-1-1", so it opens step 1's hidden file input; step 2's "Upload" button then finds no file. The other 19 upload boxes are correct. With every page written out by hand, the same structure was edited in many places, which is also why the history has bulk-edit scripts: sed loops to rewrite links (cd1f80a) and a BeautifulSoup script to change the step boxes (f72427e), both later deleted.

6. Traps, in one place

  • Saving on every keystroke with a plain INSERT adds a row per keystroke; debounce the saves and upsert on a unique key (e6b7d15).
  • A path joined onto __dirname is relative to the file's own folder, not the project root (9150ddf).
  • express.static(__dirname) serves the server's own source, its credentials and anything else in that folder (e6b7d15 to today).
  • Database credentials written into server.js, models.js and models/models-lo.js stay in git history even after they are moved out.
  • A step was named three ways: heading text, step number and string ID. A database keyed on display text loses data when the text is edited.
  • The page's string IDs and the database's integer keys did not match until ed03d07.
  • A dependency used for two days before it was declared in package.json (b9acda8 to ed03d07).
  • A GET that creates rows means reading a page changes the database.
  • The README went stale within an hour: written at 00:26, file uploads working by 01:41.
  • Hand-copied page structure leads to slips such as the mislabelled Browse button, and to bulk-edit scripts.
  • In the plan: an admin password on the command line; no ID mapping; pam_mkhomedir creates local folders rather than mounting the server's; hand edits to PAM files that Debian manages; one administrator's OneDrive token for everyone.

7. General lessons

One stable ID per thing Decide once what identifies a step (or a pupil, or a prize), make it independent of wording and position, and use it everywhere: in the HTML, in every table and in every API. Display text changes; IDs must not.
Serve a folder made for serving A web server's static folder should contain only what any visitor may download. Source, configuration, dumps and uploads belong somewhere else.
Saving often needs two halves Debouncing reduces how often you save; making the save an upsert makes it harmless to save again. Either alone leaves a problem.
Read the "how" before trusting the "what" A plan can describe the right outcome ("home folders follow the user") with a mechanism that cannot deliver it (pam_mkhomedir). Its own test would have found the gap, which is the argument for running the test on one machine before the other nineteen.
Declare what you use If the code needs a package, it goes in package.json in the same commit. "It works here" only proves the package is installed here.

9. Test yourself

What four things does a Linux machine need before an AD user can sign in to it? Membership of the domain (a computer account, from net ads join), a way to look up users and groups (NSS, with winbind in nsswitch.conf), a way to check passwords (PAM, with pam_winbind), and a home folder.
What do wbinfo -u and getent passwd each prove? wbinfo -u proves Winbind itself can list domain users. getent passwd proves the rest of the system can see them through NSS. The first can work while the second does not, if nsswitch.conf is wrong.
Why does a domain member need an ID-mapping backend such as rid? Linux uses numeric UIDs and AD uses SIDs. The backend turns one into the other, and a deterministic one gives the same user the same UID on every machine and on the file server, which shared home folders depend on.
The plan's PAM settings include pam_mkhomedir. Would a file made on one machine appear on another? No. pam_mkhomedir creates an empty local folder from /etc/skel; it mounts nothing. The server's share has to be mounted at login (for example with pam_mount or an automounter).
How does a PXE boot reach the Debian installer? The network card asks DHCP for an address; the reply also names a boot server and file; the card downloads that boot program over TFTP; it loads the installer, which installs over the network. dnsmasq can supply both DHCP and TFTP.
Why put the pilot machines on their own VLAN? To keep their traffic, and especially the pilot's own DHCP server, away from the school network, where a second DHCP server would hand out wrong addresses.
Why would one shared rclone.conf not give every pupil their own OneDrive? The OneDrive token in it belongs to whoever signed in when it was created. Each pupil needs their own token, created by signing in themselves.
Typing a note created dozens of rows. What two changes fixed it, and what does each do? A one-second debounce, so a burst of typing sends one save; and an upsert, ON CONFLICT (phase, step) DO UPDATE, so a save replaces the step's note instead of adding a row. The upsert needs a unique constraint on (phase, step).
Why is keying notes on the heading text fragile? If a heading is reworded, the next page load looks for a different key and the old note is orphaned. A stable ID that never appears on screen avoids it.
What did express.static(__dirname) in plan/server.js expose? Every non-dot file in plan/: the server's source and model files with the database password, the database dumps and, if started from plan/, the uploaded files.
Why did the tick boxes not save until ed03d07? The page identified each box by a string such as sub-step-1-1-1, while the database model used an integer primary key looked up with findByPk. The fix keyed checkboxes on the string stepId.

11. Glossary

Active Directory (AD)
Microsoft's directory of users, groups and computers, which also checks passwords (using Kerberos) for every machine in the domain.
Domain member
A computer with its own account in AD, allowed to ask the domain controllers to check users' passwords.
Kerberos realm
The Kerberos name for the AD domain, usually its DNS name in capitals; set as realm in smb.conf.
Samba / Winbind
Samba is the open-source implementation of Windows file sharing and domain protocols; winbindd is the part that makes AD users and groups appear as Linux users and groups.
NSS (Name Service Switch)
How Linux looks up users, groups and hosts; /etc/nsswitch.conf lists the sources to ask, such as files and winbind.
PAM
Pluggable Authentication Modules: the configurable chain that decides how a login is checked and what happens when a session opens.
ID mapping (idmap)
Turning AD's SIDs into Linux UIDs and GIDs; a deterministic backend gives the same numbers on every machine.
VLAN
A separate logical network carried on the same physical switches.
PXE
Booting a computer from the network: DHCP gives the address and the boot file's location, TFTP delivers it.
dnsmasq
A small server that can provide DHCP, DNS and TFTP together.
Ansible
A tool that configures many machines over SSH from an inventory and playbooks, so every machine ends up the same.
rclone mount
Shows a cloud store such as OneDrive as a local folder through FUSE, fetching files when they are opened.
OAuth token
A credential a service issues after a person signs in, letting a program act for that person without their password.
Debounce
Waiting until events stop arriving for a set time before acting, so a burst of events causes one action.
Upsert
Insert a row, or update it if one with the same key already exists (INSERT … ON CONFLICT … DO UPDATE in PostgreSQL).
ORM (Sequelize)
A library that maps database tables to JavaScript objects; sync({ alter: true }) changes tables to match the models when the app starts.
localStorage
Storage inside one browser on one machine; nothing in it reaches the server or another device.
